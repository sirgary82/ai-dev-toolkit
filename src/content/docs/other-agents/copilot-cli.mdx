GitHub Copilot CLI brings GitHub's autonomous software engineering capabilities directly to your terminal. Authenticated through your GitHub identity, it merges local shell execution with deep cloud context from your GitHub repositories, issues, pull requests, and security policies.

<Callout type="warning">
  **Prerequisites:** GitHub Copilot CLI requires an active GitHub Copilot subscription (Individual, Business, or
  Enterprise). If your organisation manages your Copilot seats, an administrator must allow CLI agent access in the
  organisation policy settings.
</Callout>

---

## "What's the Jam?" — Why Developers Choose Copilot CLI

1. **The Native GitHub Context Graph:** While other terminal agents only see the local filesystem, Copilot CLI communicates natively with GitHub's APIs. It can inspect assigned issues, summarize unresolved PR review comments, fetch commit discussions, and check GitHub Actions CI statuses without leaving the terminal.
2. **Multi-Model Engine in the Terminal:** Rather than locking you into a single AI provider, Copilot CLI allows you to switch between frontier models on the fly using `/model` — including Claude 3.7 Sonnet (with hybrid thinking), OpenAI o3-mini, and GPT-4o — all covered under your single GitHub Copilot subscription.
3. **Built-In Language Server Protocol (LSP):** Copilot CLI connects to local language servers (such as TypeScript TSServer, Roslyn for C#, Pyright for Python). This gives the agent compiler-accurate semantic intelligence — jump-to-definition, reference tracking, and compiler diagnostics — dramatically reducing syntax errors.
4. **Autopilot Mode (`Shift+Tab`):** While default interactive mode prompts for confirmation before every tool call or shell command, Autopilot mode allows the agent to execute continuous loops until the task satisfies your requirements.

## Installation & Setup

### 1. Install the CLI

```bash
# macOS / Linux (official install script)
curl -fsSL https://gh.io/copilot-install | bash

# Homebrew (macOS / Linux)
brew install copilot-cli

# Windows (WinGet)
winget install GitHub.Copilot

# Cross-platform npm
npm install -g @github/copilot
```

### 2. Authentication

Launch the CLI in any directory:

```bash
copilot
```

On first run, it will provide a one-time device code. Follow the prompt to log in via GitHub in your browser. Once authorized, the CLI retains your credentials locally.

## Quickstart: How to Use Copilot CLI

### 1. Interactive REPL

Running `copilot` opens an interactive session:

```bash
cd my-repo
copilot
```

```
╭─────────────────────────────────────────────────────────────╮
│ GitHub Copilot CLI (v1.x)                                   │
│ Model: Claude 3.7 Sonnet | Status: Connected to GitHub Org  │
╰─────────────────────────────────────────────────────────────╯

> What issues are currently assigned to me in this repository?
```

Copilot will query GitHub's API, display your assigned issues, and ask:

> _"Issue #42 ('Fix memory leak in websocket reconnection') looks critical. Would you like me to create a branch and investigate?"_

### 2. Issue-to-PR Workflow

One of Copilot CLI's most powerful workflows is resolving issues directly from the terminal:

```bash
> Checkout a new branch for issue #42, find the leak in src/network/socket.ts, write a test case, and verify it passes.
```

Copilot will:

1. Run `git checkout -b fix/issue-42-websocket-leak`.
2. Inspect `src/network/socket.ts` using LSP diagnostics.
3. Locate the unremoved event listener on socket close.
4. Update the code and add a regression test.
5. Run your test runner to verify the fix.
6. Propose a commit message referencing `Fixes #42`.

### 3. Addressing Pull Request Reviews

When a teammate or CI bot leaves review comments on your PR, Copilot CLI can review and resolve them:

```bash
# View PR status directly in the terminal
> /pr view 156

# Ask Copilot to address comments
> Read the review comments on PR #156 from @sarah and implement the requested changes.
```

## Useful Slash Commands

Copilot CLI includes built-in slash commands for session control:

| Command    | Action                                                                         |
| :--------- | :----------------------------------------------------------------------------- |
| `/model`   | Open the interactive model picker (Claude 3.7 Sonnet, OpenAI o3-mini, GPT-4o). |
| `/lsp`     | View status and diagnostics for connected Language Server Protocol instances.  |
| `/pr view` | Display status, checks, and comments for the current branch's PR.              |
| `/mcp`     | List and inspect connected Model Context Protocol servers.                     |
| `/restart` | Hot-restart the agent process while preserving your conversational context.    |
| `/update`  | Check for and apply the latest CLI updates immediately.                        |

## Autopilot Mode vs Interactive Mode

You can toggle between safety and autonomous speed at any point:

- **Interactive Mode (Default):** Copilot describes each action (creating a file, editing a function, executing `npm test`) and pauses for your keyboard confirmation (`[Y/n]`). This is best when exploring unfamiliar code or sensitive production scripts.
- **Autopilot Mode:** Press **`Shift+Tab`** to toggle Autopilot mode. In this mode, Copilot executes its plan autonomously, running tests, fixing errors, and continuing until the task objective is reached or an unexpected error occurs.

## Context Configuration: AGENTS.md & Repository Instructions

Copilot CLI natively ingests two levels of repository context:

1. **`AGENTS.md`:** The universal cross-tool specification file at the repository root. Copilot reads your build commands, test patterns, and off-limits directories.
2. **`.github/copilot-instructions.md` & `.github/instructions/*.md`:** Official GitHub Copilot instruction files used across VS Code, GitHub.com, and Copilot CLI.

```markdown
# AGENTS.md / .github/copilot-instructions.md

## Repository Guidelines

- Stack: TypeScript 5.7, Node 22, Express
- Commands:
  - Build: `npm run build`
  - Test: `npm test`
- Always verify that all test suites pass before proposing a git commit.
- Off-limits: Do not alter configuration files in `.github/workflows/` without explicit permission.
```

Codex CLI is OpenAI's open-source terminal coding agent (Apache 2.0). It runs locally on your workstation, reads your codebase, and executes multi-step engineering tasks — authoring code, running terminal commands, executing unit tests, and self-correcting based on compiler or test feedback.

<Callout type="note">
  **Codex CLI vs Codex Web:** Codex CLI is the local terminal harness that interacts directly with your local files and
  git repository. OpenAI also offers **Codex Web** (at chatgpt.com/codex), a cloud-based agent running inside remote
  container sandboxes. This guide focuses on the local **Codex CLI**.
</Callout>

---

## "What's the Jam?" — Why Developers Choose Codex CLI

Among terminal agents, Codex CLI has a distinct engineering personality:

1. **Deep Reasoning with OpenAI o-Series Models:** By default, Codex CLI leverages OpenAI's reasoning models (such as `o3` and `o4-mini`). It natively allocates test-time compute to plan intricate logic, analyze circular dependencies, and verify edge cases before generating code.
2. **Explicit Sandboxing & Execution Tiers:** Codex CLI was designed from day one with enterprise security in mind. It has three strict approval policies (`suggest`, `auto-edit`, `full-auto`), making it safe to adopt in risk-sensitive environments.
3. **Dedicated Plan Mode:** Instead of jumping straight into editing files, Codex allows you to explicitly trigger an upfront architectural planning phase where it drafts an implementation strategy, reviews project constraints, and waits for your confirmation.
4. **Headless Scriptability (`codex exec`):** Codex CLI can run entirely non-interactively in CI/CD pipelines, pre-commit hooks, or cron jobs for automated refactoring, dependency bumping, and issue remediation.

## Installation & Setup

### 1. Install the CLI

```bash
# Global install via npm
npm install -g @openai/codex

# Homebrew (macOS / Linux)
brew install --cask codex
```

Binary downloads are also available directly from the [OpenAI Codex GitHub Releases](https://github.com/openai/codex/releases).

### 2. Authentication

You can authenticate using your existing ChatGPT subscription or a direct OpenAI API key:

```bash
# Launch interactive login
codex

# Select "Sign in with ChatGPT" (works with Plus, Pro, Team, and Enterprise)
```

Alternatively, set an API key for metered billing:

```bash
export OPENAI_API_KEY="sk-..."
codex
```

## Quickstart: How to Use Codex CLI

### 1. Interactive REPL

Launching `codex` in any project folder opens the interactive agent session:

```bash
cd my-project
codex
```

```
╭─────────────────────────────────────────────────────────────╮
│ OpenAI Codex CLI                                           │
│ Model: o3 | Policy: auto-edit | Context: AGENTS.md loaded   │
╰─────────────────────────────────────────────────────────────╯

> Add a rate-limiting middleware to our Express API using redis
```

Codex will:

1. Scan your project files and parse your `AGENTS.md`.
2. Propose a plan and search for existing middleware patterns.
3. Automatically edit the appropriate files (under `auto-edit` mode).
4. Run your test suite (`npm test`) to verify that existing routes still work.
5. Present a clean unified diff for your final review.

### 2. Using Plan Mode for Multi-File Changes

When dealing with cross-cutting changes, invoke **Plan Mode** to force Codex to think through the architectural blast radius before making edits:

```bash
# Start with high reasoning effort
codex --plan --reasoning-effort high
```

During Plan Mode, Codex investigates the repository, lists all files that must change, identifies potential breaking changes, and asks:

> _"I plan to update 4 files and add 1 migration. Here is the step-by-step plan. Proceed with implementation? [Y/n]"_

### 3. Non-Interactive Scripting (`codex exec`)

For scripted automations, use headless execution:

```bash
# Run a single task non-interactively
codex exec "Update all deprecated React 18 createRoot calls to React 19 standards" \
  --approval-mode full-auto \
  --output diff.patch
```

## Execution Policies & Safety Modes

Codex provides three distinct execution tiers to balance autonomy against developer oversight:

| Mode            | Flag                        | File Edits                            | Shell / Test Commands                         | Recommended Context                        |
| :-------------- | :-------------------------- | :------------------------------------ | :-------------------------------------------- | :----------------------------------------- |
| **`suggest`**   | `--approval-mode suggest`   | Proposes diffs; user applies manually | Asks for confirmation before every command    | Initial evaluation; security-critical code |
| **`auto-edit`** | `--approval-mode auto-edit` | Applies edits automatically           | Prompts user before running terminal commands | **Default day-to-day workflow**            |
| **`full-auto`** | `--approval-mode full-auto` | Applies edits automatically           | Runs commands autonomously without prompting  | Dockerized sandboxes, isolated CI jobs     |

You can set your default policy in `~/.codex/config.toml`:

```toml
[defaults]
model = "o3"
approval_mode = "auto-edit"
reasoning_effort = "medium"

[sandbox]
allow_network = false
allowed_commands = ["npm test", "dotnet test", "git status"]
```

## Project Context: AGENTS.md

Codex CLI treats `AGENTS.md` as its primary project instruction file. Place one at the root of your repository:

```markdown
# AGENTS.md for Codex CLI

## Stack & Architecture

- ASP.NET Core 9 Minimal API + PostgreSQL
- Use MediatR for CQRS command handlers
- Return `Result<T>` objects, never throw raw HTTP exceptions

## Testing Discipline

- Run `dotnet test` to verify any modifications
- All new endpoints must have a corresponding integration test in tests/Api.Tests/

## Safety Rules

- Never edit database migrations directly
- Do not touch files under /legacy/
```

Codex automatically merges root `AGENTS.md` files with subdirectory `AGENTS.md` files when working inside nested modules, giving local component rules precedence over global rules.

## Connecting External Tools via MCP

Codex supports the Model Context Protocol (MCP) to access external tools and databases:

```toml
# ~/.codex/config.toml
[mcp_servers.postgres]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost:5432/app_dev"]

[mcp_servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "ghp_..." }
```

Once configured, Codex can query database schemas or GitHub issues directly during an interactive coding session.

## Good Practices & Pro-Tips

- **Keep reasoning effort proportional:** Use `--reasoning-effort low` for straightforward boilerplate or documentation tasks, and `--reasoning-effort high` for subtle concurrency bugs, mathematical algorithms, or complex refactors.
- **Provide verification commands in AGENTS.md:** Always document your test and lint commands in `AGENTS.md`. Codex uses these commands to self-correct failures before prompting you.
- **Inspect diffs with git:** While Codex shows its proposed changes in the terminal, run `git diff` in another terminal tab or worktree to review the full syntax-highlighted changeset before committing.
